# Ревью площадок — что проверяют и почему

Не чек-лист ради чек-листа: каждый пункт — причина реального отказа у реальных приложений.
Проверяй до отправки, не после первого отказа.

## Разрешения и приватность

- **Каждое системное разрешение** (камера, геолокация, уведомления, микрофон) — с
  человекочитаемой строкой-причиной (`NSCameraUsageDescription` в iOS, runtime-описание в
  Android) в текущем, не шаблонном виде («нужен доступ к камере» без объяснения зачем —
  частая причина отказа).
- **iOS: Privacy Manifest** (`PrivacyInfo.xcprivacy`) — декларирует, какие API «обязательной
  отчётности» (reason API: файловый таймстамп, доступ к системным логам, user defaults и т.д.)
  использует приложение и зависимости; отсутствие манифеста у затронутых зависимостей — частая
  причина отказа начиная с требований Apple 2024–2025.
- **Android: форма Data Safety** в Play Console — какие данные собираются, передаются ли
  третьим лицам, можно ли удалить аккаунт и данные. Должна совпадать с тем, что приложение
  делает по факту, не с тем, что собирались делать на старте проекта.
- **Разрешения, которых приложение больше не использует** — убрать из манифеста/Info.plist, не
  оставлять «на будущее»: лишнее разрешение — лишний вопрос ревью.

## Согласованность с листингом

- Скриншоты (`store-screenshots`) показывают реальный текущий интерфейс, не прошлую версию —
  несоответствие между скриншотом и фактическим приложением после установки отклоняется.
- Описание не обещает того, чего приложение не делает сегодня (функция в разработке, функция за
  paywall без пометки) — пересекается с анти-подделкой из `honesty.md` в `runway`.
- Возрастной рейтинг и категория соответствуют содержимому (контент для взрослых, азартные
  механики, пользовательский контент без модерации — частые причины занижённого рейтинга).

## Техническое

- **Минимальная поддерживаемая версия ОС протестирована на реальном устройстве или официальном
  симуляторе этой версии**, не только указана в `pubspec.yaml`/Gradle — старое устройство иначе
  рисует самим API, не только медленнее работает.
- Приложение не падает при первом запуске без сети и без ранее выданных разрешений — это первый
  сценарий, который проверяет ревьюер.
- Нет тестовых/debug-экранов, доступных из продакшен-сборки (скрытый свайп на «debug menu»,
  тестовый эндпоинт по умолчанию) — ревью находит такое чаще, чем кажется.
- In-app purchases (если есть) используют системный биллинг площадки для цифровых товаров;
  обход через внешнюю ссылку на оплату для цифрового контента — почти гарантированный отказ в
  iOS, у Android правила мягче, но меняются — проверяй текущие правила площадки, не прошлогодние.

## После отказа

- Причина отказа — из официального письма/консоли площадки, процитирована точно, не
  интерпретирована по памяти о похожем прошлом случае: формулировки и акценты правил меняются
  между версиями guideline чаще, чем кажется интуитивно.
- Один отказ — один цикл правок, не пакет из пяти не связанных между собой изменений в одной
  повторной отправке: так яснее, что именно устранило причину, если отклонят снова.
