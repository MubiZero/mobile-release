# Подпись — ключи не касаются рук

## Android

- Keystore (`.jks`/`.keystore`) и его пароли (`storePassword`, `keyPassword`, `keyAlias`) не
  хранятся в репозитории ни в каком виде — ни файлом, ни закодированными в `key.properties`.
- Сам keystore-файл — вне git (`.gitignore`), путь к нему на машине сборки известен заранее.
  Пароли — через `secret`: `secret get android-keystore-pass`, `secret get android-key-pass`,
  подставляются в `key.properties` или в переменные окружения сборки в момент сборки, значения
  не печатаются и не остаются в истории шелла.
- `android/key.properties` (путь, alias, две переменные с паролями-плейсхолдерами) — в репозиторий
  можно, если пароли в нём читаются из `System.getenv(...)` в `build.gradle`, а не записаны
  текстом.
- Потерянный keystore нельзя восстановить и нельзя заменить для уже опубликованного приложения
  без нового пакета (новый `applicationId`) — резервная копия keystore обязательна, храни её так
  же, как сам пароль (не в репозитории, в месте, которое переживёт потерю одной машины).

## iOS

- Сертификат подписи и провижининг-профиль — через Xcode automatic signing (Apple сам
  поддерживает актуальность) там, где это возможно; ручное управление сертификатами — только
  когда автоматика не подходит (несколько target'ов с разными bundle id, enterprise-дистрибуция).
- `.p12` (сертификат с приватным ключом) и `.mobileprovision` — не в репозитории. Приватный ключ
  сертификата живёт в Связке ключей (Keychain) машины сборки; экспорт `.p12` для другой машины —
  тоже с паролем через `secret`, не общим чатом и не почтой.
- API-ключ App Store Connect (для автоматизированной загрузки, `AuthKey_XXXXXXXXXX.p8`) — файл
  тоже не в репозитории; его Key ID и Issuer ID не секретны сами по себе, но сам `.p8`-файл
  секретен и не подлежит повторной выдаче при утере без создания нового ключа.

## Общее

- Увидел любой из перечисленных файлов или паролей, открыто лежащий в репозитории или в
  истории git — это утечка (R4 из `working-style`): сказать сразу, предложить ограничить доступ
  и перевыпустить ключ/пароль, не молчать и не чинить втихую.
- Подпись меняется (новый keystore, новый сертификат) только по явной команде владельца — старое
  приложение перестаёт получать обновления с новой подписью без миграции пользователей, это
  необратимое по факту решение, даже если технически обратимое.
