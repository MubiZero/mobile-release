# mobile-release: от собранного кода до стора

Готовый, протестированный код и готовая сборка для стора — не одно и то же. Между ними: версия,
которая не конфликтует с прошлой, подпись, которая не попадает в репозиторий, флаги сборки,
которые включают обфускацию и не включают debug-инструменты, и метаданные, которых требует
ревью площадки. Пропустить любой из них — не ошибка в коде, а отказ на этапе, где её поздно
чинить за часы до пилота.

## Когда применять

- Явная просьба собрать/подписать/отправить релизную сборку Flutter-приложения.
- Если ведёт `runway` и дошёл до G1 (чистая сборка) или G6 (бюджеты) для мобильной части —
  подробности здесь, сам G-критерий остаётся в `runway`.
- Не для: веб-части продукта (Go, см. стек владельца), самих скриншотов листинга
  (`store-screenshots`), генерации иконки приложения.

## Поток

1. **Версия.** `pubspec.yaml`: `version: X.Y.Z+B` — семвер для человека, `B` (build number) для
   площадок, он должен строго расти от последнего **отправленного** билда (не от последнего в
   git — если прошлая отправка была откачена вручную через консоль, git может не знать об этом).
   Спроси, если неочевидно, что считать последним отправленным. Патч/минор/мажор — по
   содержимому релиза (баги/фичи/breaking), не механически.
2. **Подпись — см. [references/signing.md](references/signing.md).** Ничего из этого раздела не
   бывает в репозитории: ни keystore, ни `.p12`, ни `.mobileprovision`, ни пароли ни в каком
   виде, ни в чате. Используй скилл `secrets`.
3. **Сборка.** Release-режим, обфускация, символы сохранены для будущей расшифровки падений:
   ```
   flutter build appbundle --release --obfuscate --split-debug-info=build/symbols
   flutter build ipa --release --obfuscate --split-debug-info=build/symbols
   ```
   `--split-debug-info` пишет символы в указанную папку — храни её (не в сторе, не в репозитории
   публично) для `flutter symbolize` на будущих крэшах; без неё обфусцированный стектрейс
   нечитаем навсегда. Обфускация — не граница безопасности (Dart остаётся читаем при желании),
   это защита от тривиального разбора, не от целенаправленного.
4. **Бюджеты (G6 в runway).** Размер `.aab`/`.ipa`, время холодного старта на реальном
   устройстве (не симуляторе/эмуляторе — там быстрее, чем у человека) — если runway ведёт
   релиз, числа идут в его отчёт; если нет, назови их явно, не только «собралось».
5. **Ревью площадок — см. [references/review-checklist.md](references/review-checklist.md).**
   Разрешения с человекочитаемой причиной, приватность (манифест iOS, форма Data Safety в Play),
   согласованность со скриншотами (`store-screenshots`) и текстом листинга, минимальная
   поддерживаемая версия ОС действительно протестирована, а не просто указана в конфиге.
6. **Отправка — только по явной команде, этап за этапом.**
   - iOS: архив через Xcode/`xcodebuild -exportArchive`, загрузка через Transporter или
     `xcrun altool`/`notarytool`-эквивалент App Store Connect API, сначала внутренний TestFlight,
     внешний — после. Кнопку «Submit for Review» нажимает владелец или по его явному «отправляй».
   - Android: Play Console или Play Developer API, сначала internal testing track, дальше
     staged rollout (например 10% → 50% → 100%) с паузой на мониторинг крэшей между ступенями,
     не сразу 100%.
   - «Собрал и подписал» ≠ «отправил»: не путай эти два слова в отчёте владельцу.

## Красные линии

- Keystore, сертификаты, провижининг-профили, пароли, API-ключи площадок — никогда в репозиторий,
  коммит, лог или ответ в чате. `secret get` внутри `$(...)`, значение не печатать — как во всём
  остальном, см. скилл `secrets`.
- Отправка на ревью, публикация, staged rollout на следующую ступень — только по явной команде
  владельца, одна строка про эффект перед действием (R5 из `working-style`).
- Не уменьшай целевую версию ОС или не отключай проверку подписи ради того, чтобы сборка прошла:
  назови конфликт, предложи правильный путь.
- Отклонение ревью площадкой — читай причину из официального ответа площадки, не из догадки по
  похожим прошлым случаям: формулировки меняются чаще, чем кажется.
